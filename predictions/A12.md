# A12 — few radios sending fast in place of many sending slowly

*Registered 2026-10-20 before any ns-3 run of the cells below. Plan: `docs/AUTHBC Revision
Plan.md`, A12 (it prepares B2). Never edited after the first run; outcome appended below a line.*

## Why

A hardware capacity test with eight radios (B2) can stand for 124 nodes only if delivery
depends on the total offered frame rate N·f and not on how it is split among nodes.

## What is run

`ns3/run_nmax_direct.py --plan experiments/nf-equivalence/plan.txt --out-stem
ns3_nf_equivalence`: the published scenario and source (send instant redrawn uniformly in each
period), 30 seeds of 20 s. The paper's two frames at the N·f of their crossings:

| frame | splits (N, f frames/s) | N·f |
|---|---|---|
| design, 173 B | (124, 12.5) = cell D, (62, 25), (31, 50), (16, 97), (8, 194) | ≈ 1 550 |
| baseline, 146 B | (70, 25), (35, 50) = cell C, (18, 97.5), (9, 195), (5, 350) | ≈ 1 750 |

and cell C at N = 29 (the corrected equivalent of the (5, 350) split, below the published grid).

**The (N − 1)/N correction, as scored.** Each of N nodes contends with the other N − 1, whose load
is (N − 1)·f. A split is compared with the paper's configuration at its own rate f₀ (12.5 or
50 /s) at N_eq = 1 + (N − 1)f/f₀ nodes, read from the 30-seed reference curve by linear
interpolation (the published runs of D; C's published runs plus N = 29 from this campaign).

Predictions (the model): `results/raw/nf_equivalence_predictions.csv`, the access-rule model
(nothing fitted), 30 seeds per split. Analysis: `analysis/nf_equivalence.py --score`.

## Predictions — the plan's, verbatim

> delivery is the same within 0.01 for N ≥ 16. For small N it is slightly higher, because a node
> never collides with itself. A correction factor of (N − 1)/N on the contending load brings all
> splits within 2%.

Scored as: (1) |V(split) − V(reference split)| ≤ 0.01 for design N ∈ {62, 31, 16} and baseline
N ∈ {70, 18}; (2) V(split) > V(reference split) for design N = 8 and baseline N ∈ {9, 5};
(3) |V(split) − V_ref(N_eq)| ≤ 0.02 for every split.

* **A12-1.** Each split's ns-3 V lies in the model's ±0.005 band (the model has matched ns-3's
  delivered fraction within 0.0023 at 153 points, all at ≤ 50 frames/s per node; up to 350 /s
  is new ground for it).
* **A12-2.** Plan (1) holds for design N = 62, 31 and baseline N = 70, 18; at design N = 16 the
  model puts the difference at 0.0098, so that cell is decided by sampling.
* **A12-3.** Plan (3) holds with room: the corrected residual is positive and grows as N falls
  (fewer, faster nodes still deliver a little more than their equivalent: a node's own frames
  queue behind each other instead of contending). Each ns-3 residual lies within ±0.003 of the
  model's column above.

## Disclosure

The model values above were computed before this commit (`analysis/nf_equivalence.py
--predict`, and the reference curve's model values at N_eq by the same model). No ns-3 run of
an `NF*` cell, or of C at N = 29, exists.

## What this cannot show

That radios behave as ns-3's stations do at 200–350 frames/s each: a real driver's queue and
frame bursting (F75) are not in the simulator. That is what B1/B2 would test.
